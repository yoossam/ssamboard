# 수업 보드·즉석 퀴즈 — 설계 합의·구현·검토 (2026-11-28)

선생님 결정(11-28):
- 쌤보드는 **업무 보드 + 수업 보드** 두 개로 간다.
- 수업 보드는 시간표·차시별로 미리 만드는 곳이 아니라 **수업 중에 바로 시키는 곳**이다.
  - 흐름: "퀴즈 만들어" → 구글 설문 또는 쌤보드 자체 설문 → 학생 응답 → AI 가 결과를 표·그래픽으로 정리.
- 캔바·틸더스·구글 자료 연결은 2단계다.
- 그래서 [LESSON_PREP](LESSON_PREP_2026-11-28.md)·[LESSON_SET](LESSON_SET_2026-11-28.md)의 차시 표 안은 **방향이 바뀐 옛 안**이다.

## 1. 세 모델 설계 합의(Claude 초안 → Codex·제미나이 비판)

| 물음 | Claude 초안 | 바뀐 것(합의) |
|---|---|---|
| 지금 보는 보드 | 서버에 사용자별 저장 | **기기마다**: 화면이 `X-Board` 머리글을 보낸다. 교실 TV 에 수업 보드를 띄운 채 휴대폰으로 업무 보드를 봐도 TV 가 바뀌지 않는다 |
| 응답 저장 | 표(data_rows) | **따로 쌓는 응답 표**(quiz_responses). 표 칸을 고치거나 문항이 바뀌어도 원본이 깨지지 않는다. 시작한 퀴즈의 문항은 고치지 않는다 |
| 공개 입구 | 쿠키로 중복 막기, IP 제한 | 교실 와이파이는 IP 하나라 **IP 제한은 넉넉히**, 대신 **퀴즈마다 상한**을 둔다. 쿠키는 '이미 냄' 안내만 한다(태블릿을 돌려 쓰는 반). 숨은 칸으로 봇을 거르고, 교사가 **숨기기·링크 바꾸기·비우기**를 할 수 있다 |
| 조작 수 | 계획 → 승인 → 크게 보기 | **요청 → 미리보기 → [퀴즈 시작] 한 번**. 승인하면 학생 주소가 바로 크게 열린다. AI 정답을 확인하는 단계(미리보기)는 남긴다 |
| 그래픽 | — | 막대는 **앱이 직접** 그린다(빠르고 숫자가 정확하다). AI 는 마감 뒤 **해석만** 한다 |
| 개인정보 | 번호·별명 | 번호·별명도 반에서는 누구인지 알 수 있으니 '익명'이라 부르지 않는다. AI 에는 집계만 보낸다(번호·별명 없음, 단답은 가림 처리를 거친다) |

## 2. 만든 것(1단계, 서버 판)

- **두 보드**
  - `boards.kind`(work·class, 사용자당 하나씩).
  - 위쪽 **[업무 | 수업]** 전환. 기기에 기억하고(localStorage), 요청마다 `X-Board` 를 보낸다.
  - 서버는 AsyncLocalStorage 로 요청마다 보드를 고른다(`common/board-context.ts`).
  - 오래 걸리는 일은 보드를 직접 넘긴다.
    - AI 응답은 처음에 잡은 보드를 끝까지 쓴다.
    - 계획 승인은 계획에 적어 둔 보드(`ai_commands.board_kind`)의 id 를 넘긴다.
  - 수업 보드는 쓰는 법 메모 하나로 시작한다. 빠른 단추는 [퀴즈 만들기][O·X 퀴즈][결과 정리]다.
- **즉석 퀴즈**
  - AI 도구 `create_quiz`(계획 → [퀴즈 시작]). 문항은 객관식(2~6)·O·X·단답(채점 안 함)이고 20문항까지다.
  - 자동 마감은 기본 2시간이고, 응답은 200명까지다.
  - 학생: `/q/<열쇠>`
    - 로그인 없이 번호·별명으로 답한다.
    - 스크립트 없는 HTML 폼이다. 좁은 CSP, `Referrer-Policy: same-origin`.
    - 다른 사이트에서 낸 것(Origin 다름·null)은 받지 않는다.
    - 오류가 나도 고른 답은 남는다.
    - 정답·해설은 보내지 않는다.
  - 교사: 퀴즈 블록·크게 보기(TV)
    - 받는 중에는 **결과를 가린다**. 보드가 TV 에 떠 있으면 학생이 정답을 본다(재검토에서 찾음).
    - [결과 미리 보기]는 교사가 누를 때만 연다. 마감하면 문항별 막대와 정답(✓)·정답률(50% 미만 빨강)이 보인다.
    - [AI 정리]: `quiz_results` 로 집계를 읽고 많이 틀린 문항·오답·다시 설명할 점을 정리한다.
  - 되돌리기: 학생 응답이 있으면 퀴즈와 블록을 남긴다.
  - 자료 옮기기(내보내기·드라이브 맞춤)에 퀴즈 표 두 개를 넣었다.
- **드라이브 판**
  - 학생이 들어올 서버가 없어 쌤보드 퀴즈는 안 된다. AI 가 구글 설문으로 안내한다.
  - 두 보드 전환은 된다.

## 3. 검토

- **1차(Codex·제미나이, 변경 전체)**: 실제 문제로 확인된 것을 모두 고쳤다.
  - 드라이브 판의 전역 보드 값 경합: AI·승인은 보드를 직접 넘긴다.
  - 동시 제출로 상한 초과, 제출과 되돌리기·마감·링크 바꾸기의 경합: 퀴즈 줄을 잠그고 다시 확인한다. 실제 서버에서 동시 30건, 상한 5 → 5건만 저장됨을 확인했다.
  - 받는 중 결과 노출 경로(휴대폰 타일의 정답률, 상태줄의 평균, 미리 보기 상태가 다시 열 때 남음).
  - 외부 사이트 대리 제출(Origin 검사), 400 때 답 유실, 문항 id escape.
- **문제가 아니었던 것**(코드·실험으로 확인)
  - JSON 본문 요청에서 보드 문맥이 끊기는지: 실제 서버로 확인했다. 수업 보드에 정확히 놓인다.
  - 기존 DB 에 보드가 여럿이라 유니크 인덱스가 실패할 가능성: 운영 DB 를 확인했다. 사용자당 1개다.
  - 휴대폰 메뉴 블록 누름이 위로 전해지는 문제: 누르기 처리는 머리줄에만 있다.
  - `keys.board` 직접 사용처: 모두 `boardKey()` 로 바꿨다.
- **2차(Codex, 고친 것만)**: 남은 1건을 고쳤다.
  - `no-referrer` 때문에 우리 폼도 `Origin: null` 을 보내 바깥 제출과 가릴 수 없었다. `same-origin` 으로 바꾸고 null 을 거절한다.
  - 실제 브라우저에서 제출되는 것을 확인했다.

## 4. 확인한 것 / 못 한 것

- 확인함
  - 타입 검사.
  - 시험: 공용 26·서버 64·브라우저 트랙 2. 퀴즈 흐름 시험을 더했다: 수업 보드에서 계획하고 업무 보드에서 승인해도 수업 보드에 놓이는지, 응답·봇·보기 밖 값·마감·되돌리기.
  - 사용 안내 검사.
  - 드라이브 판 빌드.
  - 실제 서버 + 임시 DB 로: 학생 페이지 GET·POST, CSP, 정답 안 새는지, 동시 제출, Origin, 같은 기기 재제출 안내.
  - Playwright: PC 전환·새로 고친 뒤 기억, 블록·크게 보기·마감·AI 정리 단추, 휴대폰 학생 화면.
- 못 함
  - 실제 AI 열쇠로 "퀴즈 만들어" → 계획까지(유료 API 를 쓰지 않는 규칙). AI 도구 흐름은 시험의 가짜 단계로만 확인했다.
  - 실제 학생 기기 여러 대, 교실 와이파이, 실제 TV.
- **QR 코드는 아직 없다.**
  - QR 을 그리는 바깥 라이브러리(`qrcode-generator`, MIT·의존 없음)를 설치하려 했으나 권한 확인에서 막혔다.
  - 이 컴퓨터에는 만든 QR 을 읽어 확인할 도구도 없어 직접 짜지 않았다.
  - 지금은 학생 주소를 크게 보이고 [주소 복사]를 둔다. 선생님이 설치를 허락하면 크게 보기에 QR 을 더한다.

## 5. 다음(2단계)

- 캔바 연결(OAuth) 자료 불러오기와 틸더스(런치패드·학생 링크) 연결: [LESSON_SET](LESSON_SET_2026-11-28.md) 1절의 연결 가능 여부를 그대로 쓴다.

# 2단계 — 수업 자료 블록·틸더스 앱 추천(2026-11-28 저녁)

## 세 모델 합의
- 순서는 **A 수업 자료 → C 틸더스 → B 구글 설문 퀴즈**로 정했다.
- **D 캔바 OAuth 는 미룬다**(Codex·제미나이). 교사마다 캔바 개발자 앱을 등록해야 해서 문턱이 높고, API 로 기존 디자인을 고칠 수도 없다. 캔바 링크를 붙여 넣으면 대부분 된다.
- 조작 수를 줄인다: 붙여 넣기 → 제목 자동 → 바로 열기. 추천 읽기에는 승인을 두지 않고, 담기는 내가 누른 것만 한다.
- '학생에게 보이기'가 원본 권한을 주지는 않는다. 그래서 안내하고, 학생에게는 편집 주소 대신 **보기 주소**만 내보낸다.

## 만든 것
- **수업 자료 블록**(`links`)
  - 링크 30개까지 둔다. https 만 받는다.
  - 종류는 주소 모양으로 정한다: 캔바·구글 슬라이드/문서/시트/설문/드라이브·유튜브·틸더스·패들렛·띵커벨·카훗·에듀넷·아이스크림.
  - 큰 단추로 하나씩 새 탭에 연다.
  - ⋯ 메뉴: 학생에게 보이기·이름 바꾸기·위로·빼기.
  - 휴대폰에서도 단추로 보인다.
  - 학생용 공유 링크는 '학생' 항목만, 보기 주소(구글 `/preview`·설문 `/viewform`·드라이브 `/view`·캔바 `/view`, `resourcekey` 유지)로 만들고 실제 도메인을 함께 보인다.
- **틸더스 앱 추천**
  - 공개 도구 `find_apps_for_lesson` 이라 열쇠가 필요 없다. 서버 판에서 HTTP JSON-RPC 로 부른다.
  - 8초 제한, 사용자당 분당 20회, 1MB 상한.
  - 블록의 [틸더스] → 주제·학교급·학년·교과 → 추천(이유·접속 안 됨 표시) → [담기].
  - 드라이브 판에서는 브라우저에서 바로 부르는 것이 막혀 있어 단추를 숨긴다.
- **AI 도구**: `add_links`(계획 → 승인, 이미 담긴 주소는 뺌), `tuilders_find_apps`(읽기, 바깥 글은 자료로만).
- **두 기기 동시 고침**: 화면이 읽은 목록(`items_base`)과 지금 저장된 목록이 다르면 409 로 막는다.

## 검토
- Codex·제미나이 1차에서 나온 것을 고쳤다.
  - 학생 주소 변환 빈틈(u/0·설문 편집·드라이브 파일·캔바 짧은 경로).
  - 동시 고침 덮어쓰기, 빈 제목 블록 대상 잃음, 중복 주소.
  - 공유에서 한 항목이 이상하면 목록 전체가 사라짐.
  - 틸더스 SSE·크기, 드라이브 판 단추, 메뉴 닫힘, 초·중 고르기.
- 문제가 아니었던 것: '되돌리기가 뒤에 고친 것을 지운다' — 기존 되돌리기가 적용 뒤 고친 블록은 건너뛴다.
- Codex 2차에서 나온 것도 고쳤다: resourcekey, 같은 요청 안 중복, 제목과 함께 저장.
- 남긴 것(낮음): 여러 줄로 나뉜 SSE 이벤트 하나, 응답을 다 받은 뒤 크기 확인(content-length 가 없을 때).

## 확인한 것 / 못 한 것
- 확인함
  - 시험: 공용 26·서버 73(링크·주소 변환·틸더스 해석·시간 초과·서명)·브라우저 트랙(add_links 새 블록·더하기·중복·409·되돌리기).
  - 드라이브 판 빌드.
  - 실제 서버 + 임시 DB + Playwright: 붙여 넣기·잘못된 주소 막기·새 탭 열기·학생 표시·**실제 틸더스 추천 4개**·담기·학생용 공유 링크에는 학생 항목만 `/preview` 로. 콘솔 오류 0.
- 못 함: 실제 캔바·구글 원본 권한에 따라 학생이 여는지(원본 설정에 달렸다).
